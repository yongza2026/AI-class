# 카페 운영관리 프로그램 제품 요구사항 문서(PRD)

- 문서 상태: MVP 범위 확정본
- 작성일: 2026-10-12
- 대상 데이터: `매장운영데이터.xlsx`, `매장운영데이터.json`, `데이터설명.md`
- 제품 가칭: 카페 운영관리

## 1. 자료에서 확인한 내용

### 1.1 자료 성격과 기간

- 자료는 실제 매장 기록이 아니라 **프렙 카페를 가정해 만든 샘플 데이터**다.
- 기록 시작일은 2025-07-01이며, 판매·재고·비용 기록은 2026-09-18까지 마감되어 있다.
- 영업 달력은 2026-09-30까지 있지만, 2026-09-19 이후 12일은 아직 마감되지 않은 미래 일정이다.
- 금액 단위는 원(KRW)이며 부가세를 제외한 금액이다.
- 재료 수량 단위는 g, ml, 개다.
- 엑셀과 JSON은 같은 기록을 담은 두 가지 파일 형식이므로 한 형식만 가져와야 한다.

### 1.2 포함된 기록

| 기록 | 수량 | 주요 내용 |
|---|---:|---|
| 공급사 | 3 | 공급사 ID와 이름 |
| 재료 | 11 | 단위, 구매용량, 가격, 납기와 안전재고 일수 |
| 메뉴 | 8 | 메뉴명, 판매 기준가, 분류, 레시피 버전 |
| 레시피 | 22 | 메뉴 한 개에 필요한 재료량과 일부 채널 전용 재료 |
| 재료 가격 이력 | 33 | 날짜별 구매가격과 구매용량 |
| 영업 달력 | 457 | 영업 여부, 마감 여부, 날씨, 메모 |
| 판매 기록 | 6,112 | 일자·메뉴·판매 채널별 수량, 할인, 매출, 수수료, 당시 원가 |
| 초기 재고 | 11 | 첫 영업일 전 재료별 수량 |
| 재고 기록 | 1,515 | 입고, 폐기, 실사조정 |
| 월 비용계획 | 120 | 월별 비용항목과 계획 금액 |
| 비용 기록 | 3,560 | 날짜별 비용 금액 |

판매 채널은 매장과 포장 두 가지다. 재고 기록에는 입고, 폐기, 실사조정이 있으며 실제로 센 수량이 있는 실사 기록도 포함된다. 비용은 임차료, 인건비, 보험료, 관리비, 수도광열비, 통신·소프트웨어, 광고비, 소모품·청소비로 구분되어 있다.

### 1.3 기획 시 주의할 점

- 판매 한 행은 주문 한 건이 아니라 **하루·메뉴·판매 채널별 합계**다.
- 월 비용계획과 날짜별 비용기록은 같은 비용을 월·일 단위로 나타낸 것이다. 둘을 지출로 함께 더하면 비용이 중복된다.
- 미래의 미마감 날짜는 매출 0인 날이 아니다. 실적, 예상, 미마감을 서로 구분해야 한다.
- 빈칸은 해당 없음 또는 미입력이고 숫자 0과 다르다.
- 재료 구매가격은 포장 전체 가격이고, 레시피 수량은 메뉴 한 개에 사용되는 양이다.
- 채널 표시가 없는 레시피 재료는 모든 채널에 적용되고, 포장 전용 재료는 포장 판매에만 적용된다.
- 과거 판매 기록에 저장된 당시 원가와 수수료는 과거 사실이다. 앞으로의 수익성·전망·비용 배분·재고 판단 기준과 혼용하면 안 된다.
- 연간 조회에는 완전한 1년이 아닌 일부 기간만 포함될 수 있으므로 조회 기간을 함께 보여줘야 한다.
- 샘플 데이터에서 검증한 구조를 실제 매장 자료에 그대로 적용할 수 있는지는 별도 확인이 필요하다.

## 2. 제품 개요

### 2.1 해결하려는 문제

카페 운영자는 판매, 비용, 재고 기록을 여러 파일에서 따로 확인해야 해 다음 질문에 빠르게 답하기 어렵다.

- 어떤 메뉴가 실제로 수익에 도움이 되는가?
- 선택한 기간의 실적과 예상 손익은 어떠한가?
- 현재 남은 재료와 부족할 가능성이 있는 재료는 무엇인가?
- 기록을 직접 고치거나 다른 기기로 안전하게 옮길 수 있는가?

### 2.2 제품 목표

운영자가 판매 기록을 입력한 뒤 메뉴 수익성, 기간 손익, 재료 잔량을 한 흐름으로 확인하게 한다. 전문 회계 지식 없이도 실제 기록과 예상 정보를 구분하여 매장 운영 결정을 내릴 수 있어야 한다.

### 2.3 핵심 사용자

- 1차 사용자: 한 매장을 직접 운영하며 판매·비용·재고를 기록하는 점주 또는 매니저 1명
- 사용 환경: 로그인 없이 한 기기에서 사용
- 협업 사용자, 회계 담당자, 여러 지점 관리자는 1차 범위에서 제외

## 3. 핵심 사용자 흐름

1. 사용자가 제공된 엑셀 양식에 기존 기록을 작성하거나 현재 엑셀 기록을 가져온다.
2. 하루·메뉴·판매 채널별 판매 합계를 입력하거나 수정한다.
3. 판매 기록이 메뉴의 수익성 정보에 반영되었는지 확인한다.
4. 같은 기간의 매출, 비용, 실적 손익과 예상 손익을 확인한다.
5. 판매에 따른 재료 사용과 입고·폐기·실사 기록이 반영된 재료 잔량을 확인한다.
6. 부족 주의 재료와 참고 발주량을 확인한다.
7. 작업 내용을 기기에 저장하고 필요할 때 백업 파일로 내보내거나 복원한다.

이 흐름에서 판매 기록, 수익성, 손익, 재고가 서로 끊기지 않는 것이 MVP의 가장 중요한 가치다.

## 4. 확정된 제품 결정

| 항목 | 결정 | 이유 |
|---|---|---|
| 저장 방식 | 한 기기의 브라우저에 저장 | 로그인과 서버 없이 4시간 내 핵심 흐름에 집중할 수 있다. |
| 기존 기록 가져오기 | 엑셀만 지원 | 비개발자가 확인·수정하기 쉽고 엑셀 양식 다운로드와 연결된다. |
| JSON 사용 목적 | 전체 데이터 백업·복원 | 엑셀 가져오기와 역할을 분리해 중복 등록 위험을 줄인다. |
| 판매 입력 단위 | 하루·메뉴·판매 채널별 합계 | 제공 자료의 구조와 일치하고 입력 부담이 적다. |
| MVP 조회 기간 | 일·주·월 | 매일 운영과 월 마감에 우선 필요한 범위다. |
| 확장 조회 기간 | 분기·반기·연간 | 긴 기간 집계는 2차 기능으로 제공한다. |
| MVP 사용 대상 | 단일 매장·단일 사용자 | 다중 사용자 기능보다 분석 흐름 완성도를 우선한다. |
| 실제 기록과 예상 | 명확히 구분해 표시 | 미래 미마감일을 실적 0으로 오해하는 것을 막는다. |

## 5. 1차 구현 범위: 4시간 MVP

### 5.1 반드시 제공할 기능

#### A. 시작과 데이터 가져오기

- 샘플 기록을 이용해 바로 기능을 확인할 수 있다.
- 판매·비용·재고 기록을 작성할 수 있는 엑셀 양식을 내려받을 수 있다.
- 정해진 엑셀 양식의 기록을 한 번에 가져올 수 있다.
- 가져오기 전 자료 형식, 필수값, 중복 가능성을 검사하고 문제가 있으면 사용자에게 알린다.
- 같은 자료의 엑셀과 JSON을 운영 기록으로 중복 가져오지 않는다.

#### B. 판매 기록 관리

- 하루·메뉴·판매 채널별 판매수량과 필요한 판매 정보를 직접 입력할 수 있다.
- 기존 판매 기록을 조회·수정·삭제할 수 있다.
- 날짜, 메뉴, 판매 채널이 잘못되었거나 필수값이 비어 있으면 저장 전에 알린다.

#### C. 비용 기록 관리

- 날짜, 비용항목, 금액을 입력할 수 있다.
- 기존 비용 기록을 조회·수정·삭제할 수 있다.
- 월 비용계획과 실제 비용기록을 서로 다른 성격의 정보로 구분한다.

#### D. 재고 기록 관리

- 재료의 입고, 폐기, 실사조정을 기록할 수 있다.
- 기존 재고 기록을 조회·수정·삭제할 수 있다.
- 재료별 현재 잔량을 확인할 수 있다.
- 잔량이 부족할 가능성이 있는 재료를 주의 대상으로 확인할 수 있다.
- 필요한 발주량을 운영 참고값으로 확인할 수 있으며, 확정 주문으로 오해하지 않도록 한다.

#### E. 메뉴 수익성 확인

- 메뉴별 판매수량, 매출, 할인, 식재료비, 포장비, 결제수수료와 수익성 결과를 확인할 수 있다.
- 과거 기록에 저장된 당시 원가를 사용한 결과와 앞으로의 예상 정보를 구분한다.
- 매장과 포장 채널의 차이를 반영할 수 있다.
- 수익성이 낮거나 확인이 필요한 메뉴를 식별할 수 있다.

#### F. 기간 실적과 예상 손익

- 일·주·월 단위로 기간을 선택할 수 있다.
- 선택한 기간의 매출, 비용, 실적 손익을 확인할 수 있다.
- 미마감 기간에는 예상 손익을 실적과 구분하여 확인할 수 있다.
- 일부 기간만 있는 연간 자료를 완전한 연간 실적으로 오해하지 않도록 실제 포함 기간을 알린다.

#### G. 저장·백업·복원

- 입력과 변경 내용은 사용 중인 기기에 유지된다.
- 전체 데이터를 JSON 백업 파일로 내려받을 수 있다.
- 백업 파일로 전체 데이터를 복원할 수 있다.
- 복원은 기존 기록에 큰 영향을 주는 작업임을 알리고 사용자의 확인 없이 실행하지 않는다.

### 5.2 MVP에서 제외할 기능

- 로그인, 사용자 권한, 여러 기기 간 자동 동기화
- 여러 매장 또는 지점 통합 관리
- POS, 카드사, 회계 프로그램, 공급사와의 자동 연동
- 실제 발주서 전송과 결제
- 분기·반기·연간 전용 분석
- 고급 예측, 자동 추천, 알림 발송
- 메뉴·재료·공급사 기준정보의 복잡한 관리
- 세무 신고, 부가세 계산, 회계 확정 기능
- 인쇄용 보고서와 맞춤형 보고서 제작

## 6. 2차 구현 범위

- 분기·반기·연간 조회와 기간 비교
- 메뉴, 재료, 공급사, 레시피, 가격 이력 관리
- 월 비용계획 입력·수정과 계획 대비 실제 비교
- 판매 추세를 반영한 예상 손익 고도화
- 납기와 안전재고를 반영한 발주 참고 기능 고도화
- 재고 부족, 입력 누락, 마감 필요 알림
- 여러 기기 동기화, 로그인, 사용자별 권한
- 여러 매장 관리와 매장 간 비교
- POS·회계·공급사 서비스 연동
- 변경 이력과 삭제 기록 확인
- 정기 백업과 클라우드 복원

## 7. 데이터 요구사항

### 7.1 반드시 구분할 정보

- 실제 마감 기록 / 미마감 기록 / 예상값
- 빈칸 / 숫자 0
- 매장 판매 / 포장 판매
- 과거 당시 원가 / 앞으로 적용할 기준
- 월 비용계획 / 날짜별 실제 비용기록
- 입고 / 폐기 / 실사조정
- 판매·비용·재고의 원본 기록 / 분석 결과

### 7.2 데이터 품질 원칙

- 메뉴, 재료, 공급사는 각 ID로 연결한다.
- 날짜, 수량, 금액, 단위와 필수 ID가 유효하지 않으면 정상 기록으로 처리하지 않는다.
- 같은 기록을 반복해서 가져올 가능성을 사용자에게 알린다.
- 삭제 또는 복원처럼 기존 자료에 큰 영향을 주는 작업은 실수로 실행되지 않게 한다.
- 가져오기 오류가 있어도 어떤 기록에 어떤 문제가 있는지 사용자가 찾을 수 있어야 한다.
- 원본 입력값과 프로그램이 만든 분석값을 구분한다.

## 8. 완료 조건

다음 시나리오를 처음부터 끝까지 수행할 수 있으면 MVP가 완료된 것으로 본다.

1. 엑셀 양식을 내려받고 정해진 형식의 기록을 가져올 수 있다.
2. 하루·메뉴·채널별 판매 기록을 새로 입력하고 수정·삭제할 수 있다.
3. 입력한 판매가 해당 메뉴의 수익성 결과에 반영된다.
4. 같은 기간의 매출, 비용, 실적 손익과 예상 손익을 구분해 확인할 수 있다.
5. 판매 및 재고 기록의 변경이 재료 잔량에 반영된다.
6. 부족 주의 재료와 참고 발주량을 확인할 수 있다.
7. 비용과 재고 기록을 각각 입력·수정·삭제할 수 있다.
8. 브라우저를 다시 열어도 저장 내용이 유지된다.
9. 전체 데이터를 백업한 뒤 복원할 수 있다.
10. 미래 미마감일, 빈칸, 월 비용계획 때문에 실적이 잘못 합산되지 않는다.

| 개발 | 2시간 | 기록 관리, 핵심 분석, 저장·가져오기·백업 연결 |
| 검사 및 수정 | 40분 | 핵심 시나리오와 주요 오류 자료 점검 |
| 배포 및 최종 확인 | 20분 | 실행 가능한 MVP와 확인 결과 |

4시간 제한 안에서는 기능의 폭보다 **판매 입력 → 메뉴 수익성 → 기간 손익 → 재료 잔량**이 실제로 이어지는지를 우선한다. 시간이 부족할 경우 2차 기능을 앞당기지 않고, 장식·고급 분석·부가 편의 기능을 줄인다.

## 10. 성공 판단 기준

- 운영자가 별도 계산 없이 판매 입력 후 메뉴 수익성과 기간 손익을 확인할 수 있다.
- 판매 기록과 재고 변동을 바탕으로 재료 잔량과 부족 주의 대상을 찾을 수 있다.
- 엑셀 가져오기와 직접 입력 결과가 같은 기준으로 조회된다.
- 실제 기록과 예상값, 빈칸과 0, 계획 비용과 실제 비용이 혼동되지 않는다.
- 사용자가 입력한 자료를 백업하고 같은 상태로 복원할 수 있다.
- 비개발자가 주요 용어와 상태를 설명 없이도 구분할 수 있다.

## 11. 이 문서에서 의도적으로 정하지 않은 사항

요청 범위에 따라 다음 항목은 이번 PRD에서 확정하지 않는다. 구현 전에 별도의 짧은 정의가 필요하다.

- 메뉴 수익성, 손익, 전망, 재료 소진, 부족 판단, 발주 참고량의 정확한 계산식
- 비용을 메뉴에 나누는 기준
- 화면 디자인과 화면별 배치
- 사용할 기술과 배포 방식의 세부 선택
- 입력·수정·삭제·가져오기·복원의 세부 동작 방식
- 실제 매장 데이터로 전환할 때의 시작 재고와 마감 기준

이 항목은 자료에 이미 합의된 값이 없으며, 샘플 파일의 과거 계산 결과를 앞으로의 정책으로 임의 적용하지 않는다.
