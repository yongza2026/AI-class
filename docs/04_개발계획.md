# 카페 운영관리 프로그램 1차 개발 계획

- 문서 상태: 확정본
- 작성일: 2026-10-12
- 기준 문서: `docs/01_PRD.md`, `docs/02_FRD.md`, `docs/03_TRD.md`
- 참고 시안: `design/stitch_cafe_profit_management_dashboard`

## 1. 전체 작업 순서

1. **EPIC 1 — 안전한 데이터 기반**
   - 자료를 저장하고 엑셀·JSON으로 옮길 수 있는 기반을 먼저 완성한다.
2. **EPIC 2 — 운영 기록과 핵심 계산**
   - 판매·비용·재고 기록과 메뉴 수익성·발주 참고값을 연결한다.
3. **EPIC 3 — 손익 대시보드와 실제 배포**
   - 앞에서 완성된 기록을 이용해 실적·예상을 보여주고, 오류 대응과 Vercel 배포까지 마친다.

이 순서로 나누는 이유는 손익과 재고 계산이 검증된 원본 기록에 의존하기 때문이다. 먼저 저장 기반을 완성하고, 그다음 기록과 계산을 연결한 뒤, 마지막에 종합 화면을 만드는 순서가 재작업을 줄인다.

- EPIC: **3개**
- User Story: **총 13개**
- EPIC별 Story: **3개 / 5개 / 5개**
- 모든 Story는 실제 저장·계산·검증을 포함하며 화면만 만든 상태는 완료로 보지 않는다.

## 2. EPIC 1 — 안전한 데이터 기반

> 상태: **완료** (2026-10-12, 자동 검사 및 사용자 확인 통과)

사용자가 자료를 불러오고 저장하며 백업할 수 있는 기반을 만든다.

### Story 1.1 — 샘플 자료로 시작하고 저장 상태 유지

#### 사용자가 할 수 있는 일

- 프렙 카페 샘플 자료를 불러올 수 있다.
- 대시보드, 판매, 수익성, 재고, 비용, 데이터 관리 화면을 이동할 수 있다.
- 브라우저를 닫았다 다시 열어도 자료를 이어서 사용할 수 있다.

#### 자동 검사

- 샘플 자료의 필수 항목과 ID 연결을 검사한다.
- 지원 브라우저와 IndexedDB 사용 가능 여부를 확인한다.
- 자료가 있는 상태에서 샘플로 교체할 때 두 번 확인한다.
- 저장 실패 시 기존 자료를 유지한다.

#### 화면 확인

1. 데이터 관리 화면에서 샘플 불러오기를 실행한다.
2. 메뉴 8개와 판매·비용·재고 기록 수가 표시되는지 확인한다.
3. 다른 화면으로 이동한 후 새로고침한다.
4. 샘플 자료가 그대로 유지되어야 한다.

### Story 1.2 — 엑셀 양식 다운로드와 전체 자료 가져오기

#### 사용자가 할 수 있는 일

- 정해진 엑셀 양식을 내려받을 수 있다.
- 작성한 엑셀을 검사한 뒤 전체 운영자료로 가져올 수 있다.
- 잘못된 자료의 시트·행·열과 오류 이유를 확인할 수 있다.

#### 자동 검사

- 파일 형식, 필수 시트와 열 이름을 검사한다.
- 날짜·숫자·단위·빈칸과 0을 구분한다.
- 메뉴·재료·공급사·레시피의 ID 연결을 검사한다.
- 중복 판매와 원가를 계산할 수 없는 기록을 검사한다.
- 오류가 하나라도 있으면 기존 자료를 변경하지 않는다.

#### 화면 확인

1. 엑셀 양식을 내려받는다.
2. 일부 필수값을 지운 파일을 가져와 오류 위치가 표시되는지 확인한다.
3. 정상 파일을 가져온다.
4. 시트별 기록 수가 표시되고 모든 화면이 새 자료로 바뀌어야 한다.

### Story 1.3 — 전체 JSON 백업과 복원

#### 사용자가 할 수 있는 일

- 현재 자료 전체를 JSON 파일로 백업할 수 있다.
- 백업 파일을 선택해 이전 상태로 복원할 수 있다.

#### 자동 검사

- 백업 형식 버전과 필수 자료를 검사한다.
- 손상되었거나 지원하지 않는 파일은 거부한다.
- 복원 전 현재 자료가 교체된다는 확인을 받는다.
- 복원 중 실패하면 기존 자료를 유지한다.

#### 화면 확인

1. 전체 백업 파일을 내려받는다.
2. 판매 기록 한 건을 변경한다.
3. 이전 백업을 복원한다.
4. 변경 전 기록과 계산 결과가 동일하게 돌아와야 한다.

### EPIC 1 완료 기준

- 샘플과 정상 엑셀을 실제 브라우저 저장소에 저장할 수 있다.
- 새로고침 후에도 자료가 유지된다.
- 잘못된 가져오기는 기존 자료를 훼손하지 않는다.
- JSON 백업·복원 전후의 기록이 일치한다.
- 데이터 관리 화면에서 위 결과를 직접 확인할 수 있다.

## 3. EPIC 2 — 운영 기록과 핵심 계산

> 상태: **완료** (2026-10-12, 단위·저장·Chrome 핵심 흐름 검사 통과 및 사용자 일괄 확인)

판매 입력에서 수익성, 비용, 재고 잔량과 발주 참고값까지 연결한다.

### Story 2.1 — 판매 기록 관리

#### 사용자가 할 수 있는 일

- 일자·메뉴·채널별 판매 합계를 입력할 수 있다.
- 판매 기록을 일·주·월, 채널, 메뉴명으로 조회할 수 있다.
- 기존 기록을 수정하거나 삭제할 수 있다.

#### 자동 검사

- 필수값, 날짜, 정수 수량과 금액을 검사한다.
- 같은 날짜·메뉴·채널의 중복 판매를 막는다.
- 정상가격, 할인, 1.5% 결제수수료와 원가를 계산한다.
- 실 결제금액이 정상가격보다 크면 저장하지 않는다.
- 무료 판매는 확인 후 저장한다.
- 레시피나 재료가격이 없어 원가를 계산할 수 없으면 저장하지 않는다.

#### 화면 확인

1. 메뉴 15개, 실 결제금액 70,000원의 판매를 입력한다.
2. 할인과 수수료가 자동 계산되는지 확인한다.
3. 저장한 행을 수정하고 삭제한다.
4. 목록 합계와 새로고침 후 기록이 정확해야 한다.

### Story 2.2 — 메뉴별 수익성 확인

#### 사용자가 할 수 있는 일

- 기간과 판매 채널을 선택해 메뉴별 수익성을 확인할 수 있다.
- 메뉴명으로 검색하고 수익 기여 순위를 볼 수 있다.

#### 자동 검사

- 과거 판매는 저장된 당시 원가와 수수료를 사용한다.
- 새 판매는 저장 당시 만든 원가 스냅샷을 사용한다.
- 매장과 포장의 포장비 차이를 반영한다.
- 공헌이익과 공헌이익률을 FRD 공식으로 계산한다.
- 공통 운영비는 메뉴 수익성에 배분하지 않는다.
- 판매금액이 0이면 비율을 `계산 불가`로 표시한다.

#### 화면 확인

1. 같은 메뉴의 매장·포장 결과를 비교한다.
2. 포장 판매에만 포장비가 포함되는지 확인한다.
3. 판매 기록을 수정한다.
4. 판매량, 매출, 원가, 수수료와 공헌이익이 즉시 바뀌어야 한다.

### Story 2.3 — 비용 기록 관리

#### 사용자가 할 수 있는 일

- 날짜·비용항목·VAT 제외 금액으로 비용을 입력할 수 있다.
- 비용을 일·주·월과 항목별로 조회할 수 있다.
- 기존 비용을 수정하거나 삭제할 수 있다.

#### 자동 검사

- 날짜, 비용항목, 0보다 큰 금액을 검사한다.
- 같은 날짜·항목·금액이 있으면 중복 가능성을 경고한다.
- 사용자가 별도 지출임을 확인하면 중복 금액도 저장할 수 있다.
- 월 비용계획을 실제 비용으로 중복 합산하지 않는다.

#### 화면 확인

1. 소모품 비용을 입력한다.
2. 비용 목록과 기간 합계에 반영되는지 확인한다.
3. 금액을 수정한 뒤 삭제한다.
4. 손익 결과가 각 변경에 맞춰 갱신되어야 한다.

### Story 2.4 — 입고·폐기·실사조정과 현재 재고

#### 사용자가 할 수 있는 일

- 재료 입고, 폐기, 실사조정을 기록할 수 있다.
- 기록을 수정·삭제하고 변경 후 예상 잔량을 확인할 수 있다.
- 재료별 현재 잔량과 최근 실사일을 볼 수 있다.

#### 자동 검사

- 재료 단위와 입력 수량을 검사한다.
- 폐기 수량은 화면에서 양수로 받고 재고 감소로 저장한다.
- 실사조정량은 실측수량과 계산 잔량의 차이로 계산한다.
- 최신 실측수량을 해당 날짜의 마감 잔량으로 사용한다.
- 음수 재고는 숨기지 않고 경고한다.
- 수정·삭제 실패 시 이전 기록을 유지한다.

#### 화면 확인

1. 재료를 입고해 잔량이 증가하는지 확인한다.
2. 일부를 폐기해 잔량이 감소하는지 확인한다.
3. 실측수량을 입력해 조정량이 자동 계산되는지 확인한다.
4. 각 기록을 수정·삭제했을 때 잔량이 다시 계산되어야 한다.

### Story 2.5 — 부족 재료와 참고 발주량 확인

#### 사용자가 할 수 있는 일

- 부족 가능성이 있는 재료를 확인할 수 있다.
- 예상 사용 가능 일수와 참고 발주량을 볼 수 있다.

#### 자동 검사

- 최근 28개 마감 영업일의 사용량을 이용한다.
- 납기일과 안전재고 일수를 반영해 안전 목표량을 계산한다.
- 부족량을 구매용량 단위로 올림해 발주 참고량을 계산한다.
- 사용 이력이 없으면 임의 발주량 대신 `계산 불가`를 표시한다.
- 포장 전용 재료는 포장 판매에서만 차감한다.

#### 화면 확인

1. 부족 상태인 재료를 선택한다.
2. 현재 잔량, 일평균 사용량, 안전 목표량과 발주량을 확인한다.
3. 해당 재료를 입고한다.
4. 부족 상태와 발주 참고량이 자동으로 줄어들어야 한다.

### EPIC 2 완료 기준

- 판매·비용·재고를 실제로 입력·조회·수정·삭제할 수 있다.
- 판매 변경이 메뉴 수익성과 재고에 즉시 반영된다.
- 비용 변경이 손익 계산에 반영된다.
- 재고와 발주 참고값이 FRD 계산식과 일치한다.
- 판매·수익성·비용·재고 화면에서 결과를 직접 확인할 수 있다.

## 4. EPIC 3 — 손익 대시보드와 실제 배포

> 상태: **완료** (2026-10-12, 자동 검사·GitHub 저장·Vercel Production 공개 배포 확인)

완성된 기록을 종합해 실적과 예상을 보여주고, 실제 주소에서 안전하게 사용할 수 있게 한다.

### Story 3.1 — 일·주·월 실제 손익 확인

#### 사용자가 할 수 있는 일

- 일·주·월과 기준 날짜를 선택해 실제 손익을 확인할 수 있다.
- 매출, 직접원가, 결제수수료, 공헌이익, 운영비와 영업손익을 구분해 볼 수 있다.

#### 자동 검사

- 마감 기록은 확정, 미마감 실제 기록은 잠정으로 구분한다.
- 실제 비용과 월 비용계획을 중복 합산하지 않는다.
- 판매가 0원이면 이익률을 `계산 불가`로 표시한다.
- 자료가 일부 기간에만 있으면 실제 포함 기간을 표시한다.

#### 화면 확인

1. 일·주·월을 차례로 선택한다.
2. 기간별 합계와 실제 포함 기간을 확인한다.
3. 판매나 비용을 수정한다.
4. 손익 카드와 추이가 즉시 갱신되어야 한다.

### Story 3.2 — 미마감 기간 예상 손익 확인

#### 사용자가 할 수 있는 일

- 미마감 기간의 예상 매출과 예상 영업손익을 확인할 수 있다.
- 예상에 사용한 과거 영업일 수와 남은 예정 영업일 수를 볼 수 있다.

#### 자동 검사

- 최근 28개 마감 영업일의 평균을 사용한다.
- 미래 예정 휴무일은 판매 예상에서 제외한다.
- 이미 판매가 입력된 미마감일에는 예상 매출을 중복으로 더하지 않는다.
- 실제 비용이 있는 날짜에는 월 계획 비용을 다시 더하지 않는다.
- 영업 달력이나 월 비용계획이 부족하면 임의값 대신 계산 불가 이유를 표시한다.

#### 화면 확인

1. 미래 미마감일이 포함된 월을 선택한다.
2. 확정·잠정·예상 금액이 나뉘어 표시되는지 확인한다.
3. 미마감일 판매를 입력한다.
4. 해당 날짜의 예상이 잠정 실적으로 바뀌고 중복 합산되지 않아야 한다.

### Story 3.3 — 종합 대시보드와 빠른 이동

#### 사용자가 할 수 있는 일

- 매출·손익 추이, 채널 비중, 수익 기여 메뉴, 부족 재료와 최근 기록을 한 화면에서 확인할 수 있다.
- 대시보드에서 판매·비용·재고 입력창으로 바로 이동할 수 있다.

#### 자동 검사

- 모든 요약은 저장된 실제 자료와 동일한 계산 모듈을 사용한다.
- 원본 기록이 변경되면 관련 카드·차트·표를 함께 갱신한다.
- 자료가 없을 때 가짜 숫자나 차트를 만들지 않는다.

#### 화면 확인

1. 대시보드에서 판매 입력을 실행한다.
2. 매출, 메뉴 순위, 손익과 재고가 함께 바뀌는지 확인한다.
3. 부족 재료를 선택한다.
4. 재고 화면에서 해당 재료를 확인할 수 있어야 한다.

### Story 3.4 — 오류가 나도 자료를 잃지 않고 작업 계속하기

#### 사용자가 할 수 있는 일

- 잘못된 입력이나 파일의 오류 이유를 이해할 수 있다.
- 예상하지 못한 화면 오류가 발생해도 다시 시도할 수 있다.
- 키보드와 화면 읽기 기능으로 주요 입력을 사용할 수 있다.

#### 자동 검사

- 예상 가능한 오류는 입력값을 유지한 채 해당 항목 옆에 표시한다.
- 저장·가져오기·복원 실패 시 일부 자료만 반영하지 않는다.
- 화면 오류와 전체 앱 오류를 구분해 복구 화면을 제공한다.
- 모달 초점 이동, 키보드 조작, 상태 읽기, 색상 외 상태 문구를 검사한다.

#### 화면 확인

1. 필수값을 비우거나 잘못된 파일을 선택한다.
2. 오류 위치와 해결 방법이 표시되는지 확인한다.
3. 작업을 취소하거나 다시 시도한다.
4. 기존 기록이 유지되고 정상 작업을 계속할 수 있어야 한다.

### Story 3.5 — 실제 Vercel 주소에서 빠르고 안전하게 사용

#### 사용자가 할 수 있는 일

- 배포된 주소에서 프로그램을 열고 핵심 흐름을 사용할 수 있다.
- 브라우저를 다시 열어도 해당 주소의 자료를 이어서 사용할 수 있다.

#### 자동 검사

- GitHub에서 코드·검사·빌드가 통과해야 배포한다.
- 실제 운영자료가 GitHub나 Vercel 결과물에 포함되지 않았는지 검사한다.
- 외부 분석·광고·오류 수집 서비스로 자료를 전송하지 않는다.
- Chrome·Edge에서 전체 흐름, Firefox·Safari 계열에서 핵심 흐름을 검사한다.
- 저장·조회·가져오기·백업이 TRD의 속도 목표 안에 드는지 확인한다.
- 보안 헤더와 외부 네트워크 요청 여부를 확인한다.

#### 화면 확인

1. Vercel Preview에서 가상 자료로 전체 흐름을 검사한다.
2. `main`에 병합해 Production 주소를 배포한다.
3. Production에서 판매 입력부터 손익·재고 반영, 백업까지 실행한다.
4. 새로고침 후 자료가 유지되고 실제 매장 자료가 서버로 전송되지 않아야 한다.

### EPIC 3 완료 기준

- 일·주·월 실적과 예상 손익이 FRD 기준으로 계산된다.
- 대시보드의 모든 요약이 실제 기록과 연결된다.
- 오류가 발생해도 기존 자료가 훼손되지 않는다.
- 주요 기능을 키보드로 사용할 수 있다.
- GitHub 검사를 통과한 코드가 Vercel에 배포된다.
- Preview와 Production에서 가짜 동작 없이 핵심 흐름을 완료할 수 있다.

## 5. 전체 완료 기준

- EPIC 1부터 EPIC 3까지 순서대로 완료한다.
- 각 Story의 자동 검사와 화면 확인 절차를 모두 통과한다.
- PRD의 1차 필수 기능과 FRD의 FR-01~FR-24가 최소 한 Story에 포함된다.
- 계산 정확성, IndexedDB 저장, 입력 검증, 오류 처리와 파일 안전성 검사를 생략하지 않는다.
- 화면만 존재하거나 버튼이 가짜로 동작하는 상태는 완료로 인정하지 않는다.
