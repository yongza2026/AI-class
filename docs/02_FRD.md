# 카페 운영관리 프로그램 기능 요구사항 문서(FRD)

- 문서 상태: MVP 기능 확정본
- 작성일: 2026-10-12
- 기준 문서: `docs/01_PRD.md`
- 참고 시안: `design/stitch_cafe_profit_management_dashboard`
- 대상 제품: 단일 매장·단일 사용자가 한 기기에서 사용하는 카페 운영관리 MVP

## 1. 문서 목적

이 문서는 사용자가 무엇을 입력하거나 선택했을 때 프로그램이 무엇을 저장·계산하고, 화면과 파일에 어떤 결과를 보여주는지 정의한다. 개발자는 이 문서로 기능을 구현하고, 검사자는 같은 기준으로 정상 동작과 오류 처리를 확인할 수 있어야 한다.

## 2. 적용 범위와 시안 차이

### 2.1 MVP에서 사용하는 시안 요소

| 화면 | 사용하는 요소 |
|---|---|
| 대시보드·손익 | 일·주·월 기간 선택, 실적 요약, 예상 손익, 매출·손익 추이, 재고 부족 목록, 빠른 기록 입력 |
| 판매 기록 관리 | 기록 목록, 기간·채널·메뉴 검색, 판매 입력, 수정, 삭제 |
| 메뉴별 수익성 | 기간·채널 선택, 메뉴 검색, 메뉴별 매출·직접원가·결제수수료·공헌이익 확인 |
| 재고 현황·흐름 | 재료 잔량, 부족 상태, 참고 발주량, 입고·폐기·실사조정 입력, 기록 수정·삭제 |
| 비용 기록 관리 | PRD에 따라 최소 입력·목록·수정·삭제 기능을 제공한다. 상세 시안은 없다. |
| 데이터 관리 | PRD에 따라 엑셀 양식, 엑셀 가져오기, JSON 백업·복원, 샘플 데이터 기능을 제공한다. 상세 시안은 없다. |

### 2.2 시안에 있지만 MVP에서 제외하는 요소

다음 요소는 PRD의 2차 범위이거나 PRD에 없는 새 기능이므로 동작시키지 않는다. 화면에 노출하지 않는 것을 원칙으로 한다.

- 원재료 가격 변동 시뮬레이터
- 자동 운영 권고와 본사 정책 건의
- CSV 원장 및 수익성 보고서 다운로드
- 분기·반기·연간 전용 분석과 맞춤 기간 조회
- 원재료 분류별 필터: 현재 자료에는 재료 분류값이 없다.
- 클라우드 동기화 상태와 여러 기기 동기화
- 지점 선택, 사용자 계정, 매니저 권한
- 실제 발주 실행과 공급사 전송

### 2.3 PRD와 시안이 다른 부분의 적용 기준

| 항목 | 차이 | MVP 적용 기준 |
|---|---|---|
| 결제수수료 | 원본 기록은 약 1.5%, 시안은 3.0% | 과거 기록은 저장된 금액을 유지하고 새 판매는 실 결제금액의 1.5%로 계산한다. |
| 판매 입력 | 시안은 실 결제금액과 할인금액을 모두 입력 가능 | 실 결제금액만 입력하고 할인금액은 자동 계산한다. |
| 재고 입고 금액 | 시안은 VAT 포함, PRD 자료는 VAT 제외 | 모든 금액은 VAT 제외로 통일한다. |
| 판매 검색 | 시안은 영수증·전표 검색을 암시 | 자료는 주문·영수증 단위가 아니므로 기록 ID와 메뉴명만 검색한다. |
| 조회 기간 | 시안에는 맞춤 기간이 있음 | MVP는 일·주·월만 제공한다. |
| 데이터 내보내기 | 시안은 JSON/CSV | MVP는 JSON 전체 백업만 제공한다. |
| 매장 공통비 | 시안 설명처럼 메뉴별 배분 가능성이 있음 | 메뉴 수익성에는 배분하지 않고 전체 손익에서만 차감한다. |

## 3. 공통 용어와 표시 원칙

| 용어 | 의미 |
|---|---|
| 정상가격 합계 | 선택한 메뉴의 기준 판매가 × 판매수량 |
| 실 결제금액 | 할인 후 매장이 실제로 받은 판매금액. 데이터의 순매출에 해당한다. |
| 직접원가 | 판매한 메뉴에 직접 들어간 식재료비와 포장비의 합계 |
| 공헌이익 | 실 결제금액에서 직접원가와 결제수수료를 뺀 금액. 임차료·인건비 등 매장 공통비는 아직 빼지 않은 값이다. |
| 실적 손익 | 저장된 실제 판매·비용 기록으로 계산한 결과. 마감 여부에 따라 확정과 잠정으로 나눈다. |
| 잠정 실적 | 실제로 입력되었지만 영업 달력상 아직 마감되지 않은 날짜의 기록 |
| 예상 손익 | 아직 마감하지 않은 기간을 최근 실적과 월 비용계획으로 추정한 참고값 |
| 현재 잔량 | 판매에 따른 사용량과 입고·폐기·실사조정을 반영한 재료 수량 |
| 안전 목표량 | 재료가 도착할 때까지의 사용량과 안전 여유분을 합친 목표 재고 |
| 마감일 | 영업 달력의 `마감여부`가 예인 날짜 |

공통 표시 원칙은 다음과 같다.

- 금액은 원 단위로 반올림하고 천 단위 쉼표와 `원`을 표시한다.
- 비율은 소수점 첫째 자리까지 표시한다.
- 수량은 재료의 기준단위인 g, ml, 개와 함께 표시한다.
- 마감 실적은 `확정`, 미마감일에 입력된 실제 기록은 `잠정`, 계산으로 만든 값은 `예상`으로 명확히 표시하며 색상만으로 구분하지 않는다.
- 빈칸은 `미입력` 또는 `해당 없음`으로 다루며 숫자 0으로 바꾸지 않는다.
- 조회 결과에는 실제 포함 시작일과 종료일을 함께 표시한다.

## 4. 화면과 이동 기능

### FR-01. 공통 메뉴와 빠른 입력

#### 사용자 동작

- 사용자는 상단 메뉴에서 `대시보드 & 손익`, `판매 기록 관리`, `메뉴별 수익성`, `재고 현황 & 흐름`, `비용 기록 관리`, `데이터 관리`를 선택한다.
- 사용자는 어느 화면에서든 `판매 입력` 또는 `재고 기록` 빠른 버튼을 선택할 수 있다.

#### 프로그램 처리와 결과

- 선택한 메뉴의 화면으로 이동하고 현재 메뉴를 표시한다.
- `판매 입력`은 판매 입력창을, `재고 기록`은 재고 변동 입력창을 연다.
- 입력창을 닫거나 취소하면 저장하지 않고 원래 화면으로 돌아간다.
- 단일 매장·단일 사용자이므로 매장명과 사용자명은 정보 표시일 뿐 선택·로그인 기능으로 작동하지 않는다.

#### 오류·예외

- 입력 중 저장하지 않은 값이 있을 때 다른 화면으로 이동하거나 입력창을 닫으면, 작성 중인 내용이 사라진다는 확인을 받는다.
- 화면 자료를 읽지 못하면 빈 숫자를 0으로 꾸미지 않고 `자료를 불러오지 못했습니다`와 다시 시도 방법을 표시한다.

## 5. 판매 기록 관리

### FR-02. 판매 기록 조회

#### 사용자 동작

- 일·주·월 중 조회 단위와 기준 날짜를 선택한다.
- 채널을 전체·매장·포장 중 선택한다.
- 메뉴명 또는 판매 기록 ID로 검색한다.
- 목록에서 수정 또는 삭제를 선택한다.

#### 프로그램 처리와 화면 결과

- 선택 기간에 속하는 판매 기록만 보여준다.
- 각 행에 날짜, 기록 ID, 메뉴, 채널, 판매수량, 기준 단가, 정상가격 합계, 할인금액, 실 결제금액, 결제수수료를 표시한다.
- 목록 합계에는 판매수량, 할인금액, 실 결제금액, 결제수수료를 표시한다.
- 검색어는 앞뒤 공백을 제외하고 메뉴명과 기록 ID에서 찾는다.
- 결과가 많으면 여러 페이지로 나누되 필터와 검색 조건을 유지한다.

#### 오류·예외

- 결과가 없으면 `조건에 맞는 판매 기록이 없습니다`를 표시하고 새 판매 입력 버튼을 제공한다.
- 시작일 이후의 자료만 있거나 한 달의 일부만 있으면 실제 포함 기간을 함께 표시한다.

### FR-03. 판매 기록 입력

#### 입력 항목

| 항목 | 입력 방식 | 필수 | 기준 |
|---|---|---:|---|
| 판매일자 | 날짜 선택 | 예 | 유효한 날짜여야 한다. |
| 메뉴 | 등록 메뉴 선택 | 예 | 메뉴 기준가와 레시피를 함께 불러온다. |
| 판매채널 | 매장·포장 선택 | 예 | 포장은 포장 전용 레시피를 추가 적용한다. |
| 판매수량 | 정수 입력 | 예 | 1 이상이어야 한다. |
| 실 결제금액 | 원 단위 입력 | 예 | 0 이상, 정상가격 합계 이하여야 한다. |
| 할인금액 | 자동 표시 | 자동 | 사용자가 직접 수정하지 않는다. |
| 예상 원가·공헌이익 | 저장 전 미리보기 | 자동 | 저장될 당시 원가 기준을 보여준다. |

#### 프로그램 처리

1. 메뉴를 선택하면 해당 메뉴의 기준 판매가와 레시피를 불러온다.
2. 수량을 입력하면 정상가격 합계를 계산하고 실 결제금액의 기본값으로 넣는다.
3. 사용자가 실 결제금액을 바꾸면 할인금액, 결제수수료, 직접원가와 공헌이익 미리보기를 다시 계산한다.
4. 저장하면 판매 당시 기준 단가, 레시피 버전, 개당 식재료원가, 개당 포장원가와 결제수수료를 함께 보존한다.
5. 저장 성공 후 판매 목록, 메뉴 수익성, 손익, 재고 잔량을 즉시 다시 계산한다.
6. 같은 날짜·메뉴·채널의 기록이 이미 있으면 새 기록을 중복 저장하지 않고 기존 기록을 수정하도록 안내한다.

#### 화면 결과

- 저장 전 미리보기에는 정상가격 합계, 할인금액, 결제수수료, 재료별 예상 사용량, 직접원가, 예상 공헌이익을 표시한다.
- 저장 성공 시 `판매 기록이 저장되었습니다`를 표시하고 저장된 행을 목록에서 확인할 수 있게 한다.
- 판매 저장으로 재료 잔량이 부족해지거나 음수가 되면 저장은 유지하되 해당 재료를 경고한다. 실제 판매 사실을 재고 부족 때문에 버리지 않는다.

#### 오류·예외

- 필수값 누락, 잘못된 날짜, 수량의 소수·0·음수, 숫자가 아닌 금액은 저장하지 않고 해당 입력칸에 이유를 표시한다.
- 실 결제금액이 정상가격 합계보다 크면 음수 할인이 생기므로 저장하지 않는다.
- 실 결제금액 0원은 무료 제공일 수 있으므로 저장할 수 있지만 확인을 한 번 받는다.
- 메뉴 레시피, 재료 가격 또는 단위가 없어 원가를 계산할 수 없으면 누락 항목을 보여주고 저장하지 않는다.
- 판매일자보다 늦게 시작하는 재료가격만 있으면 과거 가격을 추정하지 않고 저장하지 않는다.
- 영업 달력에 없는 날짜도 실제 판매 기록은 저장할 수 있다. 다만 그 날짜가 포함된 예상 손익은 영업일정을 알 수 없다고 표시한다.

### FR-04. 판매 기록 수정·삭제

#### 사용자 동작과 처리

- 수정은 기존 값을 입력창에 불러와 FR-03과 같은 검사를 거쳐 다시 저장한다.
- 날짜·메뉴·채널·수량·실 결제금액이 바뀌면 원가 스냅샷, 공헌이익과 재료 사용량을 다시 계산한다.
- 삭제는 대상 날짜·메뉴·채널·수량을 보여주고 확인을 받은 뒤 실행한다.

#### 결과와 예외

- 수정·삭제 후 판매 목록, 메뉴 수익성, 손익, 재고 잔량을 즉시 갱신한다.
- 변경 결과가 다른 판매 기록과 같은 날짜·메뉴·채널이 되면 저장하지 않고 중복 기록을 알려준다.
- 삭제 취소 시 어떤 자료도 바꾸지 않는다.
- 저장 장치 오류가 나면 이전 기록을 유지하고 성공 메시지를 표시하지 않는다.

## 6. 판매 및 수익성 계산

### FR-05. 판매 기록 단위 계산

새 판매에는 다음 계산을 적용한다. 과거에 가져온 판매의 단가·원가·수수료는 다시 계산하지 않고 파일에 저장된 당시 값을 사용한다.

```text
정상가격 합계 = 메뉴 기준 판매가 × 판매수량
할인금액 = 정상가격 합계 - 실 결제금액
결제수수료 = 실 결제금액 × 1.5% 후 원 단위 반올림
재료 기준단가 = 판매일에 유효한 최신 구매가격 ÷ 구매용량
개당 식재료원가 = 모든 공통 레시피 재료의 (사용량 × 재료 기준단가) 합계
개당 포장원가 = 포장 판매일 때 포장 전용 재료의 (사용량 × 재료 기준단가) 합계
총 직접원가 = 판매수량 × (개당 식재료원가 + 개당 포장원가)
공헌이익 = 실 결제금액 - 총 직접원가 - 결제수수료
공헌이익률 = 공헌이익 ÷ 실 결제금액 × 100
```

예: 기준가 4,800원인 메뉴 15개를 판매하고 실제로 70,000원을 받았다면 정상가격 합계는 72,000원, 할인금액은 2,000원, 결제수수료는 1,050원이다.

실 결제금액이 0원이면 공헌이익 금액은 계산하되 0으로 나눌 수 없으므로 공헌이익률은 `계산 불가`로 표시한다.

### FR-06. 메뉴별 수익성 조회

#### 사용자 동작

- 일·주·월 기간, 전체·매장·포장 채널을 선택한다.
- 메뉴명으로 검색한다.

#### 프로그램 처리와 화면 결과

- 메뉴·채널별로 판매수량, 실 결제금액, 할인금액, 식재료비, 포장비, 결제수수료, 공헌이익, 공헌이익률을 합산한다.
- 전체 채널에서는 같은 메뉴의 매장·포장을 합산하되 채널 차이를 확인할 수 있게 구분값을 제공한다.
- 공헌이익 금액이 큰 순서로 수익 기여 순위를 보여준다.
- 수익 상태는 공헌이익률을 기준으로 다음과 같이 표시한다.

| 공헌이익률 | 상태 |
|---:|---|
| 80% 이상 | 매우 좋음 |
| 70% 이상 80% 미만 | 좋음 |
| 65% 이상 70% 미만 | 보통 |
| 65% 미만 | 개선 필요 |
| 계산 불가 | 확인 필요 |

- 메뉴 수익성은 임차료·인건비 등 공통비를 배분하지 않은 공헌이익임을 화면에 설명한다.

#### 오류·예외

- 기간 내 판매가 없으면 0원 순위표를 만들지 않고 `판매 기록이 없습니다`를 표시한다.
- 원가 스냅샷이 비어 있는 과거 기록은 해당 행을 `원가 확인 필요`로 표시하고, 원가 및 공헌이익 합계에서 제외된 기록 수를 알린다.
- 음수 공헌이익도 그대로 표시하며 0으로 바꾸지 않는다.

## 7. 비용 기록 관리

### FR-07. 비용 조회·입력

#### 사용자 동작

- 일·주·월 기간과 비용항목을 선택해 목록을 조회한다.
- `비용 입력`을 선택하고 날짜, 비용항목, VAT 제외 금액을 입력한다.

#### 프로그램 처리와 화면 결과

- 비용항목은 손익 템플릿 기준의 인건비, 사업주 부담 보험료, 대표 월 보수, 임차료, 관리비, 수도광열비, 통신·소프트웨어, 광고비, 소모품·청소비, 회계·보험·수선 등, 감가상각비(비현금), 지급이자, 기타 운영비를 기본으로 제공한다. 재료비는 재고 기록에서, 결제수수료는 판매 기록에서 계산하므로 비용에 중복 입력하지 않는다.
- 새 비용은 실제 비용기록으로 저장하고 내부 구분을 `직접 입력`으로 남긴다.
- 목록에는 날짜, 비용항목, 금액, 기록 구분을 표시하고 기간 합계를 보여준다.
- 저장·수정·삭제 후 손익을 즉시 다시 계산한다.
- 월 비용계획은 예상 손익 계산에만 사용하고 이 화면에서 입력·수정하지 않는다.

#### 오류·예외

- 날짜·비용항목·금액이 비어 있거나 금액이 0 이하이면 저장하지 않는다.
- 같은 날짜·항목·금액의 기록이 있으면 중복 가능성을 경고한다. 별개의 실제 지출일 수 있으므로 사용자가 확인하면 저장할 수 있다.
- 월 비용계획과 실제 비용기록을 같은 날짜의 실제 비용으로 합산하지 않는다.

### FR-08. 비용 수정·삭제

- 수정은 기존 값을 불러와 FR-07과 같은 검사를 수행한다.
- 삭제 전 날짜·항목·금액을 보여주고 확인을 받는다.
- 성공 후 비용 합계, 실적 손익과 예상 손익을 갱신한다.
- 취소 또는 저장 실패 시 이전 기록을 유지한다.

## 8. 재고 기록과 잔량

### FR-09. 재고 현황 조회

#### 화면 결과

- 모든 재료에 대해 재료명, 현재 잔량, 단위, 최근 실사일, 일평균 사용량, 예상 사용 가능 일수, 안전 목표량, 부족 상태, 참고 발주량을 보여준다.
- 부족 재료를 먼저 확인할 수 있게 상태를 표시한다.
- 재료 분류값이 없으므로 시안의 원두·베이커리·소모품 분류 필터는 사용하지 않는다.
- `새로고침`은 저장된 기록을 다시 읽어 같은 계산을 수행하며 외부 서비스와 동기화하지 않는다.

#### 오류·예외

- 사용량 자료가 없으면 사용 가능 일수와 발주량을 `계산 불가`로 표시한다.
- 음수 잔량은 0으로 고치지 않고 음수값과 `기록 확인 필요` 경고를 표시한다.
- 단위가 서로 다른 기록은 임의 환산하지 않고 해당 재료 계산을 중단한다.

### FR-10. 입고 기록

#### 입력 항목과 처리

- 사용자는 변동유형 `입고`, 날짜, 재료, 입고수량, 공급사, VAT 제외 구매금액, 사유를 입력한다.
- 날짜·재료·입고수량은 필수이며 수량은 0보다 커야 한다.
- 공급사는 재료의 기본 공급사를 먼저 보여주며 변경할 수 있다.
- 구매금액이 있으면 단위 구매원가를 `구매금액 ÷ 입고수량`으로 계산해 입고 기록에 보존한다.
- 입고를 저장하면 현재 잔량에 수량을 더하고 부족·발주 상태를 다시 계산한다.
- 입고 구매금액은 재고 기록의 참고값이며 MVP에서는 재료가격이력을 자동 변경하지 않는다.

#### 오류·예외

- 재료 기준단위와 다른 단위는 저장하지 않는다.
- 공급사가 비어 있어도 입고는 저장할 수 있지만 `공급사 미입력`으로 표시한다.
- 구매금액이 비어 있으면 단위원가는 미입력으로 저장한다. 0원은 빈칸과 구분한다.

### FR-11. 폐기 기록

- 사용자는 변동유형 `폐기`, 날짜, 재료, 폐기수량, 사유를 입력한다.
- 화면에는 양수로 입력하지만 저장 시 재고 감소값으로 처리한다.
- 저장 전 예상 잔량을 보여준다.
- 폐기 후 잔량이 음수가 되면 경고와 확인을 거친다. 확인하면 실제 폐기 사실은 저장하고 기록 점검 대상으로 표시한다.

### FR-12. 실사조정 기록

- 사용자는 변동유형 `실사조정`, 날짜, 재료, 실제로 센 수량과 사유를 입력한다.
- 조정량은 `실측수량 - 조정 직전 계산 잔량`으로 계산한다.
- 저장 전 계산 잔량, 실측수량, 조정량을 보여준다.
- 실측수량은 0 이상이어야 하며 0은 실제 재고가 없다는 뜻으로 저장할 수 있다.
- 가장 최근 실사일의 실측수량을 그날 마감 잔량으로 본다. 이후 현재 잔량은 그 다음 날부터의 판매·입고·폐기·조정만 반영한다.
- 같은 재료·날짜에 실사가 이미 있으면 중복 저장하지 않고 기존 실사를 수정하도록 안내한다.

### FR-13. 재고 기록 수정·삭제

- 수정은 기록 유형에 맞는 입력값을 다시 검사하고 예상 잔량을 보여준 뒤 저장한다.
- 삭제 전 기록과 변경될 예상 잔량을 보여주고 확인을 받는다.
- 수정·삭제 후 현재 잔량, 부족 상태, 참고 발주량과 손익 관련 직접원가 표시를 다시 읽는다.
- 실사 기록을 삭제하면 그 이전 실사 또는 초기재고부터 잔량을 다시 계산한다.
- 결과가 음수가 되면 변경은 숨기지 않고 경고한다.

### FR-14. 재고 및 발주 참고 계산

재료별 계산은 다음 기준을 사용한다.

```text
판매 사용량 = 판매수량 × 해당 메뉴의 재료별 레시피 사용량
일평균 사용량 = 최근 28개 마감 영업일의 판매 사용량 합계 ÷ 사용한 마감 영업일 수
실사 전 계산 잔량 = 초기재고 + 입고 + 폐기 + 실사조정 - 판매 사용량
실사 후 현재 잔량 = 최근 실측수량 + 실사 다음 날부터의 입고·폐기·조정 - 실사 다음 날부터의 판매 사용량
예상 사용 가능 일수 = 현재 잔량 ÷ 일평균 사용량
안전 목표량 = 일평균 사용량 × (납기 영업일 + 안전재고 영업일)
필요량 = max(0, 안전 목표량 - 현재 잔량)
참고 발주 묶음 수 = 필요량 ÷ 구매용량을 올림한 정수
참고 발주량 = 참고 발주 묶음 수 × 구매용량
```

- 현재 잔량이 안전 목표량보다 작으면 `부족 주의`로 표시한다.
- 참고 발주량은 자동 주문이 아닌 참고값임을 항상 표시한다.
- 마감 영업일이 28일보다 적으면 존재하는 마감 영업일만 사용한다. 한 날도 없으면 계산 불가다.
- 일평균 사용량이 0이면 사용 가능 일수와 발주량을 계산하지 않는다.
- 포장 전용 재료는 포장 판매에서만 차감한다.

## 9. 대시보드와 기간 손익

### FR-15. 기간 선택

- 사용자는 일·주·월 중 하나와 기준 날짜를 선택한다.
- 주는 월요일부터 일요일, 월은 달력의 첫날부터 마지막 날로 정의한다.
- 미래 날짜가 포함되어도 미마감일을 매출 0원 실적으로 계산하지 않는다.
- 선택 기간 중 실제 자료가 있는 날짜와 예상 날짜를 구분해 표시한다.

### FR-16. 실적 손익

선택 기간에 저장된 실제 기록은 다음과 같이 계산한다. 마감일의 기록은 `확정 실적`, 미마감일에 이미 입력된 기록은 `잠정 실적`으로 구분한다.

```text
실 결제금액 = 판매기록의 순매출 합계
식재료비 = 판매수량 × 개당 식재료원가 스냅샷의 합계
포장비 = 판매수량 × 개당 포장원가 스냅샷의 합계
결제수수료 = 판매기록의 결제수수료 합계
직접원가 = 식재료비 + 포장비
공헌이익 = 실 결제금액 - 직접원가 - 결제수수료
실제 운영비 = 같은 마감 날짜의 비용기록 합계
영업손익 = 공헌이익 - 실제 운영비
영업이익률 = 영업손익 ÷ 실 결제금액 × 100
```

- 화면에는 실 결제금액, 직접원가, 결제수수료, 공헌이익, 실제 운영비, 영업손익을 별도 항목으로 보여준다.
- 잠정 실적은 실제 입력값이므로 0이나 예상값으로 바꾸지 않지만 확정 합계와 구분한다.
- 메뉴별 수익성과 달리 영업손익에서는 임차료·인건비 등 실제 비용을 차감한다.
- 판매가 0원이면 영업손익은 계산하되 영업이익률은 계산 불가로 표시한다.

### FR-17. 예상 손익

선택 기간에 미마감일이 있을 때만 예상값을 제공한다. 고급 예측이 아닌 MVP용 단순 참고값이다.

```text
기준 일평균 판매·직접원가·수수료
= 선택 기간 시작 전 최근 28개 마감 영업일의 각 실제 합계 ÷ 해당 영업일 수

미마감 판매 예상
= 기준 일평균 판매 × 선택 기간의 남은 예정 영업일 수

미마감 직접원가·수수료 예상
= 각 기준 일평균 금액 × 남은 예정 영업일 수

미마감 운영비 예상
= 각 월의 월 비용계획을 달력 일수로 나눈 금액 중 미마감 날짜에 해당하는 합계

기간 예상 영업손익
= 현재까지의 실제 공헌이익
 + 미마감 판매 예상
 - 미마감 직접원가 예상
 - 미마감 수수료 예상
 - 현재까지의 실제 운영비
 - 미마감 운영비 예상
```

- 월 비용계획은 미마감 날짜 예상에만 사용하고, 이미 비용기록이 있는 날짜에는 다시 더하지 않는다.
- 판매 기록이 이미 있는 미마감일은 입력값을 잠정 실적으로 사용하고 같은 날짜의 일평균 판매 예상액을 다시 더하지 않는다.
- 예정 휴무일은 판매 예상 일수에서는 제외하지만 월 운영비의 날짜 배분에서는 포함한다.
- 예상 결과에는 사용한 과거 마감 영업일 수와 남은 예정 영업일 수를 함께 표시한다.

#### 오류·예외

- 최근 마감 영업일이 없거나 영업 달력이 없으면 예상 손익을 만들지 않고 부족한 자료를 안내한다.
- 월 비용계획이 없으면 운영비가 빠진 낙관적 예상값을 보여주지 않고 `비용계획 부족으로 예상 손익 계산 불가`를 표시한다.
- 이미 전체 기간이 마감되었으면 예상값 대신 실적만 보여준다.
- 여러 달을 포함하는 주는 각 달의 비용계획을 해당 날짜에 맞게 나누어 사용한다.

### FR-18. 대시보드 결과와 연결

- 기간 요약, 매출·공헌이익 추이, 채널별 비중, 메뉴 수익 기여 상위 항목, 부족 재료를 보여준다.
- `판매 기록 입력`, `비용 지출 기록`, `재고 실사조정` 버튼은 각각 해당 입력 기능을 연다.
- 부족 재료를 선택하면 재고 현황에서 해당 재료를 확인할 수 있게 한다.
- 최근 기록은 판매·비용·재고의 저장된 사실만 보여주며 실시간 POS 연동처럼 표현하지 않는다.

## 10. 엑셀 양식과 가져오기

### FR-19. 엑셀 양식 다운로드

- 사용자가 `엑셀 양식 다운로드`를 선택하면 `.xlsx` 파일을 내려받는다.
- 양식에는 공급사, 재료, 메뉴, 레시피, 재료가격이력, 영업달력, 판매기록, 초기재고, 재고기록, 월비용계획, 비용기록, 자료정보 시트를 포함한다.
- 각 시트 첫 행은 정해진 열 이름이며, 예시 행과 작성 설명은 실제 기록으로 오인되지 않게 구분한다.
- 파일명에는 `카페운영_가져오기양식`과 내려받은 날짜를 포함한다.

### FR-20. 엑셀 가져오기

#### 사용자 동작과 처리

1. 사용자가 `.xlsx` 파일을 선택한다.
2. 프로그램은 저장하기 전에 전체 시트와 행을 검사한다.
3. 오류가 없으면 가져올 기록 수와 기존 자료가 교체된다는 내용을 보여준다.
4. 사용자가 확인하면 현재 운영자료 전체를 엑셀 내용으로 교체한다.
5. 성공 후 대시보드와 모든 목록을 새 자료로 다시 계산한다.

MVP에서는 기존 자료에 일부 행을 합치는 기능을 제공하지 않는다. 전체 교체 방식으로 중복 등록을 막는다.

#### 검사 항목

- 파일 형식과 필수 시트·열 이름
- 날짜·숫자·TRUE/FALSE·단위 형식
- 필수값과 ID 중복
- 메뉴·재료·공급사·레시피 사이의 ID 연결
- 레시피와 재료가격이 없어 판매 원가를 계산할 수 없는 경우
- 같은 날짜·메뉴·채널 판매의 중복
- 재고 기록 유형과 수량 부호
- 빈칸과 0의 구분

#### 화면·파일 결과

- 오류가 있으면 데이터를 하나도 교체하지 않는다.
- 오류 목록에는 시트명, 엑셀 행 번호, 열 이름, 입력값, 쉬운 오류 설명을 표시한다.
- 오류 목록은 화면에서 확인할 수 있다.
- 성공 시 시트별 가져온 기록 수와 자료 기준일을 표시한다.

#### 오류·예외

- 암호가 걸렸거나 손상된 파일, `.xlsx`가 아닌 파일은 읽지 않는다.
- 필수 시트가 없거나 열 이름이 바뀌었으면 올바른 양식을 다시 받도록 안내한다.
- 추가 시트는 가져오지 않고 무시한 시트명을 알린다.
- 검사 또는 저장 중 실패하면 기존 자료를 그대로 유지한다.
- 엑셀과 JSON 백업을 동시에 운영자료로 합치지 않는다.

## 11. 기기 저장·백업·복원

### FR-21. 자동 저장

- 판매·비용·재고의 저장·수정·삭제와 엑셀 가져오기·복원이 성공할 때마다 현재 기기에 저장한다.
- 화면을 다시 열어도 마지막 저장 상태를 불러온다.
- 저장 공간이 부족하거나 브라우저가 저장을 막으면 변경 완료로 표시하지 않고 사용자에게 백업과 공간 확인을 안내한다.
- 브라우저 데이터 삭제, 시크릿 모드, 기기 고장은 복구할 수 없으므로 데이터 관리 화면에 정기 백업 안내를 표시한다.

### FR-22. JSON 전체 백업

- 사용자가 `전체 백업 다운로드`를 선택하면 공급사부터 설정 정보까지 현재 전체 자료를 하나의 `.json` 파일로 내려받는다.
- 백업에는 자료 형식 버전과 백업 생성시각을 포함한다.
- 파일명은 `카페운영_전체백업_YYYYMMDD_HHMM.json` 형식으로 한다.
- 다운로드 실패 시 파일이 만들어졌다고 표시하지 않고 다시 시도 방법을 안내한다.

### FR-23. JSON 전체 복원

1. 사용자가 `.json` 백업 파일을 선택한다.
2. 프로그램은 형식 버전, 필수 자료, ID 연결과 값 형식을 검사한다.
3. 복원될 기록 수와 현재 자료가 모두 교체된다는 경고를 보여준다.
4. 사용자가 다시 확인하면 전체 자료를 한 번에 교체한다.
5. 성공 후 모든 목록과 계산 결과를 다시 만든다.

- 손상 파일, 다른 형식의 JSON, 지원하지 않는 미래 버전은 복원하지 않는다.
- 검사·저장 실패 시 현재 자료를 그대로 유지한다.
- 일부만 복원하거나 기존 자료와 합치는 기능은 제공하지 않는다.

### FR-24. 샘플 데이터 사용

- 사용자는 자료가 없을 때 프렙 카페 샘플을 불러와 기능을 확인할 수 있다.
- 현재 자료가 있으면 샘플로 교체된다는 확인을 두 번 받은 뒤 실행한다.
- 샘플임을 화면에 표시하여 실제 매장 자료로 오인하지 않게 한다.
- 취소 또는 실패 시 기존 자료를 유지한다.

## 12. 기능 간 자동 반영 관계

| 사용자 변경 | 자동으로 다시 계산하거나 갱신할 결과 |
|---|---|
| 판매 저장·수정·삭제 | 판매 목록, 메뉴 수익성, 실적·예상 손익, 재료 잔량, 부족 상태, 참고 발주량 |
| 비용 저장·수정·삭제 | 비용 목록, 실적·예상 손익 |
| 입고·폐기·실사 저장·수정·삭제 | 재고 잔량, 부족 상태, 참고 발주량 |
| 엑셀 가져오기 | 모든 목록, 손익, 수익성, 재고 결과 |
| JSON 복원 | 모든 목록, 손익, 수익성, 재고 결과 |
| 기간·채널 변경 | 현재 화면의 조회 결과만 변경하며 원본 기록은 바꾸지 않음 |

## 13. 공통 오류 및 안전 동작

| 상황 | 프로그램 동작 |
|---|---|
| 필수값 누락 | 저장하지 않고 누락된 입력칸과 이유를 표시한다. |
| 빈칸과 0 혼동 | 자동 변환하지 않고 각각 미입력과 실제 0으로 유지한다. |
| 음수 또는 잘못된 수량 | 기록 유형에 맞는 값인지 검사하고 잘못되면 저장하지 않는다. 폐기는 화면에서 양수로 받는다. |
| 중복 판매 | 같은 날짜·메뉴·채널은 새로 추가하지 않고 기존 기록 수정을 안내한다. |
| 중복 비용 | 경고 후 사용자가 별도 지출임을 확인하면 허용한다. |
| 계산 자료 부족 | 임의값을 만들지 않고 계산 불가 이유를 표시한다. |
| 삭제 | 대상과 영향 범위를 보여주고 확인 전에는 실행하지 않는다. |
| 전체 교체 | 엑셀 가져오기·JSON 복원·샘플 불러오기는 검사와 재확인 후 한 번에 실행한다. |
| 처리 중 실패 | 일부만 반영하지 않고 이전 상태를 유지한다. |
| 저장 실패 | 성공 메시지를 표시하지 않고 사용자의 입력을 가능한 한 화면에 유지한다. |
| 재고 음수 | 숨기거나 0으로 고치지 않고 경고와 기록 점검 방법을 표시한다. |
| 미마감 미래 날짜 | 실제 매출 0으로 합산하지 않고 예상 또는 미마감으로 구분한다. |
| 기간 일부만 존재 | 실제 포함 기간과 누락 기간을 표시한다. |

## 14. MVP 완료 검사 시나리오

1. 샘플 데이터를 불러오고 실제 자료가 아님을 확인한다.
2. 엑셀 양식을 내려받아 유효한 전체 자료를 가져온다.
3. 잘못된 엑셀의 시트·행·열 오류를 확인하고 기존 자료가 유지되는지 검사한다.
4. 메뉴·채널·수량·실 결제금액으로 판매를 저장하고 할인과 1.5% 수수료가 자동 계산되는지 확인한다.
5. 같은 날짜·메뉴·채널 판매의 중복이 차단되는지 확인한다.
6. 판매 수정·삭제가 수익성, 손익과 재고 잔량에 모두 반영되는지 확인한다.
7. 메뉴별 매장·포장 원가 차이와 공헌이익을 확인한다.
8. 비용을 입력·수정·삭제하고 영업손익이 갱신되는지 확인한다.
9. 입고·폐기·실사를 각각 저장하고 잔량과 참고 발주량을 확인한다.
10. 미마감 미래 날짜가 실적 0으로 합산되지 않고 예상값으로 구분되는지 확인한다.
11. 전체 JSON을 백업하고 다른 상태에서 복원해 같은 기록과 계산 결과가 나오는지 확인한다.
12. 삭제·복원·전체 교체를 취소했을 때 기존 자료가 변하지 않는지 확인한다.
13. 브라우저 화면을 다시 열어 저장한 기록이 유지되는지 확인한다.

- 고급 발주 추천과 실제 발주 전송
